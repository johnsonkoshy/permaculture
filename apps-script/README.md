# EBPG Event Hub: live version (Google Sheets + Apps Script)

The Event Hub prototype, now saving to a real Google Sheet. The page is hosted on Netlify, and the Sheet and Apps Script do the saving, emails and reminders. Both are owned by gistparent@gmail.com for now.

## Morning: 5 minutes to turn it on

1. **Approve it once.** Open the script editor link and pick **setup** in the function menu at the top. Click **Run**, then **Review permissions**, and choose your account. Google will say *"Google hasn't verified this app"*. That's normal for a script you wrote yourself: click **Advanced → Go to EBPG Event Hub (unsafe) → Allow**. This sets up the Sheet tabs and the hourly reminder check. If the organizer code is blank (a new Sheet) or still the one the first version shipped with, setup makes a new one, writes it to the Settings tab and prints it in the Execution log under the code. Share it only with organizers.
2. **Open the site and sign in.** Go to https://ebpg-event-hub.netlify.app and you'll see the Guild's landing page. Click **Sign in** and type the organizer code (see the ORGANIZER_CODE row on the Settings tab). An empty Sheet has no names to pick yet, so press **Continue**, wait for *The Guild Sheet is ready. Pick your name.*, and pick yours. That first sign-in fills the Sheet with the Guild's six events from the OPC planning notes and the team's names, roles and permissions. Contacts start blank, the volunteer list starts empty, and the posts for Workday #7 and Community Meeting #2 wait for review and their tasks need someone. Workday #7 and the past events are published; Community Meeting #2 is a draft, so only organizers see it until someone clicks **Publish**. This happens only once. Afterwards `SEEDED` on the Settings tab says TRUE, so emptying a tab by hand never brings the starter events back.
3. **If the link still says "Access Denied":** in the script editor go to **Deploy → Manage deployments → ✏️**. Set *Execute as* to **Me** and *Who has access* to **Anyone**, then click **Deploy**. Or just tell Claude, and it will redeploy.

## Before the demo

1. On the Settings tab, set `REMINDERS` to **FALSE**, so nobody gets a reminder while you set up.
2. In the script editor, pick **resetStarterData** in the function menu and click **Run**. It empties the data tabs (Events, Bringing, Posts, Activity, Volunteers, Reminders, Team, Gardens and Plants), and the plant numbers start again at 001. Headers, Settings and the Channels tab stay. It also deletes real volunteer sign-ups and the plants, so copy any you want to keep first. It can't be run from the page.
3. Open the site and sign in once (type the code, press **Continue**, then pick your name). That fills the Sheet with the starter events again. Until then the public page says *Next dates coming soon*.
4. Fill in the real contacts (email or phone): tap each person on the Team page, or type them into the Team tab. Until then the Team page shows "No contact yet", and a task given to that person says *Add a contact on the Team page*.
5. Confirm the Workday #7 date and description with Jessie, and fix them in the app or the Sheet. Confirm `WORKDAY_SCHEDULE` on the Settings tab too ("4th Sundays, 10 AM" is our best guess) and fill in `CONTACT_EMAIL` if the Guild wants one on the public page.
6. In Google Calendar, create an **EBPG Events** calendar and put its ID in `CALENDAR_ID` (Calendar settings → Integrate calendar → Calendar ID). Create a test Google Group and put its address in `GROUP_EMAIL`.
7. On the **Channels** tab, paste the real links in the `link` column: the Facebook group's page, the Instagram account, the WhatsApp or Hylo chat, and the Google Group and Calendar if you like. Until a channel has one, its row in Outreach says *Add the link on the Channels tab* where **Open Facebook group** would be.
8. Set `REMINDERS` back to **TRUE**.

## How the pieces fit

- **Netlify** serves the page (`site/index.html`). It's fast, has no Google banner, and could use the Guild's own domain later.
- **The page** sends each save as a POST to the Apps Script web app (`doPost`). Only the page's own functions (the `API` list in `src/Code.js`) can be called, and every organizer action checks the organizer code.
- **Apps Script** reads and writes the Sheet, sends email through Gmail and adds Calendar events. The hourly reminder trigger runs there too.
- **The old Google link** still works. Put `https://ebpg-event-hub.netlify.app` in `SITE_URL` on the Settings tab and it will send visitors to Netlify instead.
- **Netlify settings:** the site was created with Netlify's "visitor access: Netlify login" protection on. It was switched off so the public can open the page.

## What works

- **Landing page** for the public: upcoming events, a garden map and the volunteer sign-up. Sign-ups go to the **Volunteers** tab. The volunteer gets a welcome email and the lead organizer gets a "new volunteer" email.
  - **The volunteer form** asks for a name, an email or a phone (at least one), the best way to reach them (Email or Text), *I'd like to help with* (meeting setup, garden work days, partner projects, outreach & photos, teaching a skill, adopt a plant, host a project, partner organization), *When are you usually free?* (weekend mornings, weekday evenings, one-off projects), *How did you hear about us?*, a note, and *Add me to the Guild email list* (unticked to start; people who tick it are added to the Google Group by hand).
  - **Sending:** the button says *Sending…* until the Sheet has it, and only then does the thank-you show: *Thanks, Maya!*, then *Next up* with the next published event (or the one they came from), its date, time and place, **Add to Google Calendar**, **Download .ics** and **Directions**. If it doesn't go through, everything typed stays, the message says why, and **Try again** sends it again with the same id, so the Sheet keeps it once however many times it's sent.
  - **Host a project** and **Become a partner** under *Get involved* open the form with that choice ticked, ready for a note about the project or group. Arriving from an event's page (*I'm new: sign me up*) sends that event's id, kept in the `event` column.
  - **The Volunteers tab** has `signed up`, `name`, `contact` (the email, else the phone), `wants to help with`, `note`, `id` (8 characters, given to every row, including ones from before the column or typed in by hand), `email`, `phone`, `best way`, `free`, `heard from`, `email list` (yes or blank) and `event`. Someone who signs up again with the same email or phone (written any way: `(510) 555-0101` is `+1 510 555 0101`) and the same first name gets their row updated instead: the new choices are added, the note gets *Signed up again 2026-10-25* and what they wrote (*as Maya O* when the name they gave is different), the name stays, and there's no second welcome email (the lead gets *Volunteer signed up again: Maya*). Someone else on a shared email or phone (a household, a group's info@ address, a parent and child) gets a row of their own; the lead's email says who they share it with, and an email that's on the tab already gets no second welcome.
  - **The server checks every answer:** a name of letters, spaces and . ' - (80 characters at most), an email that looks like one, a phone with at least 7 digits, only the form's own choices, and a note of 1,000 characters at most.
  - **Against bots and floods:** the form has a box only bots fill in (`website`, off the screen) and notes when it was opened. A sign-up with that box filled in, or sent within 3 seconds of opening, is answered as if it worked and nothing is kept or sent. A second send of the same id within 10 minutes (Try again) is kept once. The same person again within the hour (a correction, say) has their answers added to their row, with no emails at all. The form times itself with a clock that a change to the device's time doesn't move, and a time below zero is never taken for a bot. After 60 sign-ups in 10 minutes the form says *Lots of sign-ups right now. Please try again in a few minutes.*
  - **The welcome email** greets them by first name (or *Hi there* when it isn't plain letters, so a name can't carry a link), says what they signed up for, names the next published event (or the one they're coming to) with a link to its page (on `SITE_URL`), and ends with *Just reply to this email if you have questions*; replies go to `REPLY_TO`. The lead's email has every answer.
  - **Only what the Sheet publishes:** *Upcoming events* shows up to four published events of any kind, soonest first, each with its type, title, date and time, and place, and a *Today*, *Tomorrow* or *This Saturday* chip when it's within a week. Drafts, cancelled events and ones that are over never show, and nothing is made up: with nothing published it says *Next dates coming soon. Join the list and we'll tell you.* The line under *Upcoming events* is `SCHEDULE_TEXT` on the Settings tab, and the Linktree links use `LINKTREE_URL`.
  - **Event links:** each card links to the event's own page, `?ev=` and the event's id (for example https://ebpg-event-hub.netlify.app/?ev=w7). Share that link anywhere: on flyers, in posts and in chats.
  - **The card fan** at the top shows the next published event, and clicking it opens that event's page. On phones it's replaced by a *Next up* strip under the heading, with a **Details** link.
- **An event's own page** (`?ev=`), for newcomers, built only from what `getPublic` hands out:
  - The type of event and its title, the date and time, the place and address with **Directions** (the event's map link, or a Google Maps search for the address), the description, *What to bring* and the good-to-know line from its tags.
  - **First time? Here's how it goes:** the timeline without the leads' own rows, *Wear closed-toe shoes and bring water.* for work days, and *Look for Jessie, who's hosting.*
  - **I'm new: sign me up** goes to the volunteer form on the home page, with a *Coming to OPC Garden Work Party* chip (its **x** takes it off). The event's id goes to the Sheet with the sign-up (the Volunteers tab's `event` column), and the thank-you and the welcome email are about that event.
  - **Also on Partiful** (or Luma, Meetup, and so on) when the event has an RSVP link.
  - **Add to Google Calendar**, **Download .ics** (for Apple Calendar, Outlook and the rest; Oakland time, with the event's link) and **Share**: the phone's share sheet where there is one, else **Copy link** and **Share on WhatsApp**.
  - **Organizer? Open the plan** goes to sign-in; once signed in, the event's plan opens. An organizer already signed in on that device who opens the link gets the plan straight away.
  - A cancelled event's link says *This event was cancelled* and shows the next events (`getPublic` lists only the ids of events cancelled in the last 30 days or later, nothing else about them). A draft, one that's over, or a link that was mistyped says *This event isn't on the calendar anymore* and shows the next events. While the Sheet wakes up the page shows grey shapes, never that note.
  - Moving between the home page and event pages doesn't load the site again, and Back and Forward work. The browser tab says the event's title.
  - **Copy link** at the top of an event, for organizers, copies the same public link. A draft's is turned off ("Publish it first to share").
- **Share previews:** a link to the site shows the Guild's name, the description and the trellis photo (`og.jpg`) in WhatsApp, iMessage, Slack and social posts. The page is one static file, so an event's link previews as the Guild, not as that event.
  - **While the Sheet wakes up** the page shows grey cards that say *Loading events…*, never events of its own. Each browser keeps the Sheet's last public answer (`ebpg-public-v1` in its local storage, public fields only) and shows it at once on the next visit while it reads the Sheet again. If the Sheet doesn't answer and there's nothing kept, the page says *We couldn't load the latest dates. See our Linktree for upcoming events.* and tries again when the visitor comes back to the tab.
- **Flyers & posts** (for organizers): a flyer, Instagram post, story and email header filled in from any event, plus a quote post, a thank-you card and a garden sign for any week.
  - A published event's flyer has a real QR code to its public page (`?ev=`), with the short link beside it (*Details and RSVP*); the story says *Details: link in bio*. A draft's flyer says *Publish to get a QR code*. The landing page's card fan shows the same flyer.
  - The thank-you card is signed by the host of the event picked above, for the day it fell on. The garden sign shows `WORKDAY_SCHEDULE` from the Settings tab and a QR code to the volunteer form on the home page (`#join`).
  - The QR codes are drawn by qrcode-generator 1.4.4 from cdnjs (an exact version, with its integrity hash). If it can't load (offline, or blocked), the pieces show the short link instead.
  - **Download** under every piece saves it as a PNG at its real size: the flyer 1700 × 2200 (US Letter at 200 dpi), the Instagram and quote posts 1080 × 1080, the story 1080 × 1920, the email header 1200 × 400, the thank-you card 2100 × 1500 (7 × 5 in at 300 dpi) and the garden sign 3600 × 2400 (24 × 16 in at 150 dpi). Files are named `ebpg-<event title>-<date>-<piece>.png`, for example `ebpg-opc-garden-work-party-2026-10-25-flyer.png` (just `ebpg-quote-post.png` and `ebpg-garden-sign.png` for the any-week pieces). The drawing is done by html-to-image 1.11.13 from cdnjs (an exact version, with its integrity hash), loaded only the first time someone clicks Download, with the Guild's Google Fonts put inside the image. If the fonts can't be fetched the image still comes, in the browser's own fonts; if the image can't be made at all, the button comes back and a note says *Couldn't make the image. Try Print instead.*
  - **Print** on the flyer, the thank-you card and the garden sign prints just that piece on US Letter: the flyer across the page, two thank-you cards with dashed cut lines between them, and the sign sideways. The colors print even with the browser's background graphics turned off, and the QR code prints sharp. *Save as PDF* suggests the same file name as Download.
  - The event pop-up's strip of pieces has the same **Download** buttons, and **Print** on its flyer.
- **Organizer sign-in** with the organizer code. You can change the code on the **Settings** tab at any time; it needs at least 8 characters, and a blank or shorter one lets nobody in ("The organizer code isn't set up yet. Ask the Sheet owner."). After 20 wrong codes in 10 minutes, every organizer call says "Too many tries. Wait 10 minutes and try again." until the 10 minutes are up, so the code can't be guessed. A page left open with the old code stops calling the Sheet as soon as it's turned down, keeps its unsaved changes and asks for the new code, so it never uses up those tries. The header shows who is signed in.
- **Test-mode banner:** while `TEST_MODE` is TRUE, every organizer page has a yellow note: "Test mode: every email goes only to *the owner*. Turn it off on the Settings tab when you're ready to go live.", with an **Open the Sheet** link. It goes away within two minutes of setting `TEST_MODE` to FALSE.
- **Saving you can see:** a note under the top bar (or under the event pop-up's own bar, while one is open) says *Saving…*, then *All changes saved*. If the Sheet doesn't answer (Apps Script can take a few seconds to wake up, or a phone loses signal), it says *Not saved* with a **Retry** button, retries on its own after 2, 5 and 15 seconds and then every minute (and right away when you come back to the tab or press Save again), and marks the event's tile *Not saved*. Saves of one event go out one at a time, newest last. "Saved" and "added" messages appear only once the Sheet has the change, and the browser asks before closing a tab with unsaved changes.
- **Staying current:** when you come back to the tab, and every 2 minutes while it's open, the page reads the Sheet again and says *Updated with the latest changes* if someone else changed something. Events with unsaved changes here, or being edited, are left alone.
- **Signing in:** the names to pick are the organizers on the Team tab (until the Sheet answers, grey shapes). When there are none to show (a Sheet nobody has set up, or one that didn't answer), **Continue** checks the code first and the names come with the Sheet's answer. The name you pick says *Signing in…* while the Sheet wakes up (the very first sign-in, which fills an empty Sheet, can take up to a minute). Tick **Remember this device for 30 days** to stay signed in on that phone or laptop; otherwise the code is forgotten when the tab closes. Sign out forgets it either way.
- **Help tab** for organizers: where the data lives (with a link to the Sheet), the organizer code, test mode, when reminders go out, hand edits, and who the lead organizer is.
- **Events:** creating, editing, the host and co-hosts, the timeline and "who's bringing what" all save to the Sheet in under a second.
- **Who's bringing what:** someone with **Assign tasks** picks each task's **Who** from the team, or from *New volunteers* (people who signed up on the home page): picking one adds them to the Team tab as a volunteer, with the email or phone they said is best to reach them (Activity: *Jessie added Maya to the team*). Each task has a status: *Needs someone*, *Not asked yet* (someone is on it but hasn't been asked), *Asked*, *Confirmed*, *Can't make it* or *Done*. A *Can't make it* row turns red, says *Find someone* and counts as open again. Tap a task's words to change them (Enter or leaving the box keeps them, Escape puts them back).
  - **Ask** opens a text (for a phone number) or an email (for an email address) to that person on your own phone or computer, already written: *Hi Phil, it's Jessie from the East Bay Permaculture Guild. Could you bring plates and cups to Workday #7 on Sun 10/25 at 10 AM? Reply yes or no. Thank you!* Nothing is sent from the Sheet. A task nobody had asked about yet becomes *Asked*. Someone with no contact on the Team page has no Ask link.
  - A task copied from an earlier event says *Last time: Phil*, and while it needs someone, **Ask Phil again** puts Phil on it as *Asked* (and opens the message when Phil has a contact).
  - Under each person, the page says how the hourly reminders reach them (see **Reminders**): *Reminders by email: Sat from 6 PM and Sun morning*, *No email: the host gets a list to text*, or *Add a contact on the Team page*.
  - The **Bringing** tab has `event id`, `what`, `who`, `status` (`open`, `asked`, `confirmed`, `cant` or `done`), `task id`, `last time` (who did it at the event it was copied from) and `type` (`food`, `tools`, `setup`, `other`...). A status typed by hand as the page words it (*Confirmed*, *Can't make it*) reads the same, and a blank one is *Asked* once someone is on it.
- **Team page:** someone with **Manage team** taps a person's row (or the contact under their name) to change their email or phone and how their reminders go (*Email* or *Text*). An email address needs Email and a phone number Text. **Remove** asks first (*Remove Karen?*), then takes them off the Team tab with 10 seconds to **Undo**, which puts them back where they were. Volunteers don't sign in; they get reminders by email, or, with only a phone, they're on the host's list to text.
- **New events:** **New event** asks for a **Type**: *Work day*, *Community meeting* or *Other* (the event's series). A work day is labeled with the next number (*Workday #8*) and starts 10 AM to 2 PM on the next 4th Sunday after the last work day and after today; a community meeting (*Community Meeting #3*) 6 to 8 PM, four weeks after the last one, or two weeks from today when there's none; Other has no number and starts a week from today. Changing the Type changes the label, and the date, times and details nobody has changed yet. **Start from** copies another event as a draft: its details, its plan, the channels it posted to (a copy of one with nothing posted on record gets the ones marked for new events), and every task, open again, with *Last time: Phil* when someone did it. The **Host** and **Co-hosts** are picked from the team; saving changes only those two roles, so a plan's other roles (*Neighborhood outreach: Marissa*) stay, and show under Hosting.
- **Cancel event:** someone with **Edit events** clicks **Cancel event** in an upcoming event's header and says why, if they like. `cancelEvent` sets the status to `cancelled`, deletes the Calendar entry it posted (a `[TEST]` one from the owner's calendar), and writes a cancellation notice as a draft for every other channel already posted (*Cancelled: OPC Garden Work Party on Sunday, October 25. Heavy rain is forecast. ...*, with a subject line for the Google Group), to approve and post as usual. The post each notice replaces stays on record: Activity says *Partiful was posted by Phil on Oct 20: https://partiful.com/e/...*, and the notice keeps that link in the Posts tab's `original post` column, so its row shows **Original post**. Partiful, Luma and Meetup are cancelled on the site itself, so their approved notice has **Open the Partiful event** (that link) instead of **Open & fill**, which would make a second listing. A Google Group email sent only as a test (status `test`: only the Sheet owner got it) gets no notice, so the real Group never hears of an event it wasn't told about; its row goes, and Activity says why. Drafts nobody posted go. Activity says who cancelled it and why. It's off the public page at once, gets no reminders, and its tile moves under *Past* with a *Cancelled* badge. A tab that hadn't seen the cancel can still save its edits, but the event stays cancelled and its notices stay.
- **Delete draft:** a draft that was never published and has nothing posted (one made by mistake) can be deleted from its header instead. It goes from the page at once, with 10 seconds to **Undo**; only then does `deleteEvent` set its Events row's status to `deleted` (the row stays, and every read skips it) and remove its Bringing, Posts and Activity rows. Switching to another tab or app keeps the 10 seconds; closing or reloading the page, or signing out, sends it at once.
- **Nothing comes back:** the Sheet adds a new Events row only for a save that says the event is new (`created: true`, sent until its first save gets through; every other save says `created: false`). A save of an event whose row was deleted or whose id was cleared by hand, or of a deleted draft, is turned down, and the page takes the event off with a note saying so. A tab opened before this update doesn't say either way, so the Sheet still adds an event from it that it doesn't have (unless that id was deleted with **Delete draft**), and the organizer's new event isn't stuck there; reload open tabs after deploying to get the full protection.
- **Drafts and publishing:** a new event starts as a **Draft**, shown with a *Draft* badge on its tile and a *Draft* pill in its header, and only organizers see it. Someone with **Edit events** clicks **Publish** in the header (Activity: *Phil published the event*), or picks *Draft: only organizers see it* / *Published: on the public site* under **Status** in Edit event. The edit form also takes an **RSVP link** (optional, e.g. the Partiful event), which must start with `https://`. The Events tab keeps them in its `status` (`draft`, `published`, `cancelled` or `deleted`) and `rsvp link` columns; a blank status counts as published, so rows from before the column stay on the public page, and a word the app doesn't know counts as a draft. Cancelled events (see **Cancel event**) get no reminders. A page left open from before this update leaves both columns as they are when it saves.
- **What the public page gets:** `getPublic` needs no code, so it hands out only an allow-list: published events from today on, each with its title, date, times, place, address, map and RSVP links (`https://` only), description, what to bring, the known tags, the photo, its type, the host's first name and the timeline without the leads-only rows; the ids of events cancelled in the last 30 days or later (only the ids); the organizers' names and roles; the gardens; and `SCHEDULE_TEXT`, `WORKDAY_SCHEDULE`, `LINKTREE_URL` and `CONTACT_EMAIL` from the Settings tab. Never the plan's notes, who's bringing what, posts, activity, contacts, permissions or the organizer code. It reads only the Events, Team, Gardens and Settings tabs and keeps its answer for 5 minutes, so lots of visitors don't slow the Sheet down. Every save from the app clears that copy, so a publish shows right away; a change typed into the Sheet by hand can take up to 5 minutes. A new volunteer's welcome email mentions only a published event.
- **Outreach review:** every post starts as a draft (*Draft · needs review*). Someone with **Approve & post** on the Team page clicks **Approve** (*Approved by Sky*); the text stays editable, and changing it sends it back to review. **Approve all drafts** approves every draft of an event at once. People without the permission see where each post stands, read-only, with who can approve it. The attention bar on the Events page says how many drafts wait for review and how many approved posts are ready, and **Review next** opens the soonest one.
- **Posting, once approved:**
  - **Google Group:** the **Post** button sends the email.
  - **Calendar:** the **Post** button adds the event.
  - **Post** says *Posting…* until the Sheet answers. The Sheet saves the event first, so the email and the Calendar entry always have the title, date, time and place on screen, even for an event created a moment ago. Only an approved post can go out, and only once: pressing Post again, or from a tab left open since before, says *Already posted* and sends nothing. The Posts row says posted only after it really went, and a save from an old tab never turns it back into a draft, or a draft back into posted. If the Sheet doesn't answer, nothing changes on the page.
  - **Test mode:** the row says *Test sent* (hover: *Test mode is on: this went only to the Sheet owner*). The email goes only to the owner, and Calendar entries go on the owner's own calendar with `[TEST] ` before the title. Once `TEST_MODE` is FALSE, a test-sent row offers **Post for real**; for the Calendar it takes the `[TEST]` entry off and adds the real one. Post for real goes out once too: pressed again, or from another tab, it says *Already posted*. If test mode is turned back on after a real post, **Update calendar** leaves the Guild calendar entry as it is until test mode is off. The Outreach summary says *Everything is posted* only once nothing is left as a test.
  - **Changes after posting:** when the title, date, start, end or place changes, the Google Group and Calendar rows say *Changed since posted*. **Update calendar** changes the entry already there (its id is in the Posts tab's `calendar id` column), with no second copy; if it was deleted, it adds a new one. **Draft an update** turns the Google Group row into a new draft, *Subject: Update: Seed swap, Sat 11/7*, which needs approving and posting like any other. The Posts tab's `stale` column says `yes` while a row is out of date.
  - **Partiful, Luma, Meetup, Facebook, Instagram and chats:** stay copy and paste (Luma's API needs a paid plan, and Partiful has none). **Copy text** puts the text on the clipboard and **Open Partiful** opens the link on the Channels tab; copying alone never counts as posted. **Mark as posted** asks for the link to the post (optional, `https://` only) and then shows *Posted by Phil · Oct 25* with **View post**. **Undo** puts it back to approved.
  - **The Posting Helper** (`chrome-extension/`, the Guild's Chrome extension): where it's installed, an approved Partiful, Luma, Meetup, Facebook or chats row has **Open & fill** (**Open Hylo & fill** for the chats) in place of Open Partiful. It hands the helper the event, the row's approved text as the description, the event's public page (`?ev=`, published events only) and the flyer as a 1020 × 1320 PNG (drawn by the same html-to-image as Download; left out if it isn't ready within 8 seconds). The helper opens the site in a new tab and fills in the form; the row then says *Opened Partiful. Review the form and publish there, then come back and mark it posted.* (Activity: *Phil opened Partiful with the Posting Helper*). It stays approved until someone marks it posted. If the helper can't open the site (a group link missing from its Options, say), the row shows its reason. Without the helper, the rows keep **Copy text**, and a **Fill forms automatically with the Posting Helper** link under the list opens the install steps, with the zip that `build.py` copies to `site/ebpg-posting-helper.zip` (the Help page has them too). The helper only runs on ebpg-event-hub.netlify.app and the dev server, so the Google-hosted page and the artifact never show Open & fill.
  - **Instagram** has **Download image** (the 1080 × 1080 post) and **Copy caption**; the chats have **Share to WhatsApp** (`https://wa.me/?text=` with the approved text).
  - **The RSVP link from Partiful:** when Partiful (or Luma, or Meetup) is marked posted with its link and the event has no RSVP link yet, the row asks *Use this as the event's RSVP link?* **Yes** saves it as the event's RSVP link (Activity: *Phil set the RSVP link to the Partiful post*), so the public event page says **Also on Partiful**, and the drafts nobody edited get an *RSVP on Partiful: …* line. Approved ones whose text changes go back to review. **No** leaves the event as it is. Only people with **Edit events** are asked.
- **Plants (Adopt a plant):** the organizers' **Plants** page, for the Guild's retention idea: *A newcomer adopts one plant, gets a reminder before each work day, and comes back to care for it.* Nothing is filled in to start. The Guild adds the plants it would like a neighbor to look after, on the page (**Add a plant**) or straight into the **Plants** tab of the Sheet.
  - **The Plants tab** has `id`, `nickname`, `plant`, `latin name`, `where`, `planted`, `status` (`needs a steward`, `requested` or `adopted`; a blank one reads as needs a steward, or adopted when the row names a steward), `steward`, `steward contact`, `backup`, `care every (days)` (1 to 60), `last care`, `care notes`, `requested by`, `requested contact`, `requested at` and `token`. A row typed in by hand gets its id (the next number: `001`, `002`, ...) and a token on the next sign-in, or the next load of the Google-hosted page. A number is never given to a second plant, even after the first is taken off the list (the script keeps the last one in its `PLANT_NO` property), so a printed tag always means its own plant. The token is the plant's own secret for links in the steward's emails and never goes to the page; leave `id` and `token` as they are. A row whose id uses anything but letters, numbers, `-` and `_`, or repeats an earlier row's, is listed on the Events page as a row to fix. Dates typed by hand read like the Events tab's.
  - **Each card** shows the nickname (or the plant), the plant and latin name, where it is, when it was planted, how often it needs care, when it was last cared for and the care notes, with a status pill. **Steward** and **Backup** pick anyone on the team or anyone who signed up on the home page (two sign-ups with one name show how to reach each). `savePlant` copies the steward's email or phone (an email first) from their Team or Volunteers row into `steward contact`, and the status follows: adopted with a steward, needs a steward without one. **Edit** opens the Add a plant form filled in and saves only what changed. **Remove** asks first, then takes the plant's row off the Plants tab.
  - **Adoption requests** (status `requested`, with someone in `requested by`) show first, with **Approve** (`approveAdoption`: the person who asked becomes the steward, with their contact, and the request columns are emptied) and **Decline** (`declineAdoption`: the request columns are emptied and the plant needs a steward again). While a request waits, nobody else can be made the steward. The Plants tab in the menu says how many wait. The public **Adopt** button that fills these in is the next step.
  - **Print tag** prints the plant's garden tag alone, 5 inches wide on a Letter page with a cut line: *Stewarded plant · no. 001*, the nickname, the plant and latin name, when it was planted, the steward's and backup's first names (*Could be you* when it needs one), and a QR code to the plant's page (`?plant=001`, for example https://ebpg-event-hub.netlify.app/?plant=001) with the short link and *Scan to follow this plant*. **Show tag** shows it on the card first. On the Google-hosted page, `?plant=` goes on to `SITE_URL` like event links. Until the public plant page is built, the link opens the home page.
  - Changing the plants needs **Edit events**; anyone signed in can print a tag. Each change goes to the Sheet at once (`savePlant`, `deletePlant`, `approveAdoption`, `declineAdoption`, each checking the organizer code and running under the lock), and the card says *Saving…* until it's there. If the Sheet doesn't answer, the form keeps what was typed, and pressing **Add plant** again never adds it twice. A change another organizer made first (a request already answered, a plant already removed) shows on the card, and the list is read from the Sheet again.
- **Drafts that link to the event:** once the event is published, the Google Group email, the Calendar entry's description, the Facebook post and the chat message end with *Details, directions and sign-up:* and the event's own page (`?ev=`, for example https://ebpg-event-hub.netlify.app/?ev=w7). A draft event's page isn't there yet, so its posts have no link until **Publish**, as its flyer has no QR code. They add *RSVP on Partiful:* and the link once the event has an RSVP link. The Partiful post has no link (it is the RSVP), and Instagram says *RSVP: link in bio.* A draft nobody has edited is written again when the event's details, its status or its RSVP link change. In the app, an approved one whose text changes goes back to review (Publish says how many: *1 approved post changed, so it needs review again*); a change typed into the Events tab by hand updates only the drafts still waiting for review. A draft whose text was fixed by hand in the Posts tab keeps the fix, and counts as edited from then on; clear its *text* and *edited* cells to have the app write it again. Posted texts never change.
- **Channels tab:** the Guild's channels, one row each: `channel` (the app's id, don't change it), `name`, `used`, `link`, `on for new events` and `how it posts`. It's filled once, when the tab is made, with Partiful, the Google Group, the Calendar, the Facebook group, Instagram and the WhatsApp & Hylo chats turned on, and Luma and Meetup off; after that the app never writes to it, so your edits stay.
  - `used` FALSE hides a channel from **Also post to** and from new events (a post that already went out stays on its event). TRUE, yes, x or 1 count as yes; anything else as no.
  - `on for new events`: the channels a **New event** starts with. **Plan next** and **Start from: Copy …** use the channels of the event they copy instead.
  - `link`: where **Open Facebook group** (and the rest) goes, `https://` only. Blank: the row says *Add the link on the Channels tab*, linked to the Sheet.
  - `name`: what the app calls it. `how it posts` is there to read: the Google Group and the Calendar post from the app, and the rest are copy and paste whatever the cell says.
  - Changes show on the next sign-in, or within two minutes on an open page. A row with an id the app doesn't know is ignored; a deleted row goes back to the app's own setting for that channel.
  - The Posts tab keeps the trail in its own columns: `posted by`, `approved by`, `approved at`, `posted at` (times in UTC, like `2026-10-25T17:03:00.000Z`), `post url`, `calendar id`, `stale` and `original post` (on a cancellation notice, the link to the post it replaces). A link that doesn't start with `https://` isn't kept. The Activity tab says *Phil approved Partiful*, *Phil copied the Partiful text*, *Phil marked Partiful as posted*, *Phil un-marked Partiful*, *Phil posted to the Google Group* and *Phil updated the Calendar*.
- **Reminders:** every hour the script checks for events. The evening before (from 6 PM) and the morning of (8 AM to noon), it emails each person bringing something, except for tasks marked *Done* or *Can't make it* and tasks with nobody on them. People with only a phone number go on a "text these people" email to the host. If Gmail refuses one, the Reminders tab gets a `failed: ...` line, the others still go out, it's tried again the next hour, and the lead organizer gets one email a day listing what failed.
- **Email limits and replies:** replies to every email go to `REPLY_TO` on the Settings tab, or to the lead organizer's email on the Team tab when that's blank. When fewer than `MAIL_RESERVE` (30) emails are left for the day, welcome and new-volunteer emails wait so reminders can still go out; each one held back is a `skipped (quota): ...` line on the Reminders tab.
- **Safe values:** the server keeps only the four known photos, `https://` map and RSVP links, known tags or plain words up to 30 characters, titles up to 200 characters, descriptions up to 4,000 and "what to bring" up to 500. Event and task ids can use only letters, numbers, `-` and `_`; an Events row with any other id is listed on the Events page as a row to fix. The page escapes everything it shows from the Sheet.
- **Gardens on the map:** a garden added to the Gardens tab by hand gets its map point from the hourly run (five an hour, using Google's geocoder), not while a visitor waits. An address Google can't find gets `not found` in its `lat` cell, so it isn't looked up again; clear that cell after fixing the address to try again. Either way the garden shows in the list under the map.
- **Hand edits:** an organizer can fix the title, date, times, place, host, co-hosts, description, notes, timeline, status or RSVP link straight in the Sheet. The app shows the change on the next load. Dates can be typed as `2026-10-31`, `10/31/2026`, `10/31`, `Oct 31, 2026` or `October 31, 2026`, and times as `10:30 AM`, `10am` or `noon`. If a date still can't be read, that event is left off the Events page and a note there says which row to fix.
- **Columns:** the app finds each column by its header in row 1, so you can move columns or add your own between them. Don't rename or delete the headers the app made. When an update needs a new column, the app adds it at the right end of the tab. Bringing, Posts and Activity are rewritten by the app on every save, so personal notes belong on a separate tab, not in new columns there. Activity keeps the newest 100 lines per event.

## Safe testing

`TEST_MODE` is **TRUE** on the Settings tab, so **every email goes only to gistparent@gmail.com**, with the real recipient shown in the subject, and organizers see a yellow test-mode note on every page. Calendar events go on your own calendar. Nothing reaches the Google Group or the team.

To go live:
1. Put the Group's address in `GROUP_EMAIL`.
2. Fill in each person's email or phone on the Team tab.
3. Set `TEST_MODE` to FALSE.

## Moving it to a Guild account

Sign in to the Guild account and open the Sheet. Use **File → Make a copy**, which copies the script too. Then, in the copy, go to **Extensions → Apps Script**, run **setup**, and use **Deploy → New deployment → Web app** (Execute as: Me, Who has access: Anyone). The new web app gets a new link. Delete this copy afterwards.

## Known limits (fine for a pilot)

- The organizer code is one shared password. Permissions inside the app, such as who can approve and post, are honor-system; the server checks only the code. Someone guessing wrong 20 times pauses sign-in for everyone for up to 10 minutes.
- If two people save the same event in the same second, the last save wins. Different events are fine.
- A plant's `steward contact` is copied when the steward is picked. A contact added on the Team page later reaches the Plants tab when the steward is picked again (the card says so).
- The volunteer form's honeypot and 3-second check stop simple bots. One that posts straight to the web app with a new email each time can still use up the 60 sign-ups for those 10 minutes (it can't use the welcome emails to flood one inbox: an address already on the Volunteers tab gets no second one).
- An event's whole plan has to fit in one cell (45,000 characters). A save over that says "This event's plan is too long to save. Shorten the notes." and the Sheet keeps the last saved version.
- Gmail allows about 100 emails a day from a free account. `MAIL_RESERVE` keeps the last 30 for reminders.
- Texts aren't sent automatically. The host gets a list of people to text instead.
- There's also an empty test project called "ebpg-api-check" in Drive. Claude made it to check access, and you can delete it.

If the Apps Script deployment URL ever changes, update `API_URL` in `build.py` and redeploy the site.

**Watch out:** Apps Script's HtmlService deletes everything after `//` on a line of inline JavaScript. It respects normal quotes but not backtick strings, so a URL or base64 inside a template literal breaks the page. `gas-safe.js` rewrites those as `/\/` and fails the build if any `//` is left. If a script error happens, the page shows a friendly bar ("Something went wrong. Please refresh the page...") with a Dismiss button, and the details go to the browser console. Browser-extension errors, cross-origin "Script error." and ResizeObserver warnings are ignored. The bar's script is `on_err` in `build.py` (Netlify) and `ON_ERROR` in `src/Code.js` (Google-hosted page). Keep the two the same; a test checks this.

`event-hub/src.html` is still the prototype artifact's source. The live build swaps in `src/bridge.js` at the `/*__GAS_BRIDGE__*/` marker. The artifact build leaves that marker as an empty comment, so the artifact keeps working as before.

**Prototype-only content** in `src.html` sits between `<!--PROTO-->` and `<!--/PROTO-->` (HTML), or `/*PROTO*/` and `/*/PROTO*/` (CSS and JS), each marker on a line of its own. `build.py` removes those blocks before it adds the bridge, and fails if the markers don't pair up. `event-hub/build.py` keeps them, so the artifact still has its sample badges, "Viewing as" picker, Google button and "How we'd build it" page. It goes the other way too: the live page's wording is in the markup, and anything only the live page shows (the organizer code field, the Help tab, the signed-in chip) has `class="live"`, which the artifact hides.
